# Trade AI 业务流程复刻版使用说明书

适用版本：当前登录演示版  
编制日期：2026 年 10 月 31 日  
适用对象：外贸业务员、销售主管、运营人员、企业管理者

## 1. 说明书说明

这份说明书面向实际使用系统的人员，说明如何完成登录、公司设置、客户管理、文档管理、AI 业务分析和日常自动化，并解释各模块之间的数据关系。

阅读时先看第 2 章和第 3 章，完成账号与公司资料配置；随后按业务目标选择对应模块。需要一次完整操作示例时，直接看第 11 章的“端到端工作流”。

系统主要提供分析、检索、内容生成和本地数据管理。对外发送邮件、社交平台发帖、加好友和正式下单仍由人工确认与执行。

## 2. 快速开始

### 2.1 启动应用

当前演示地址为：

```text
http://127.0.0.1:8019/
```

如果服务没有运行，在 `login-demo` 目录执行：

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8019
```

本机使用 Anaconda 时可执行：

```powershell
& 'C:\Users\wangdiao\anaconda3\python.exe' -m uvicorn app:app --host 127.0.0.1 --port 8019
```

应用默认只监听本机地址，不能直接作为公网系统使用。

### 2.2 注册与登录

1. 首次使用点击“注册”。
2. 输入有效邮箱，例如 `name@example.com`。
3. 密码长度为 8 到 128 位。
4. 注册成功后会自动进入工作台。
5. 已有账号在“登录”页输入注册邮箱和密码。

如果重启服务后要求重新登录，是因为当前进程默认生成了新的会话签名密钥。账号、客户、文档和对话数据不会因此丢失。设置固定的 `LOGIN_DEMO_SECRET` 环境变量后，可以让登录状态在服务重启后继续有效。

### 2.3 完成首次配置

进入工作台后，按以下顺序配置：

1. 点击左下角“⚙️”打开“模型设置”，填写模型名称和 API Key。
2. 点击左上角公司旁的“⚙”打开“公司设置”。
3. 填写公司名称、网址、行业、主营产品、地址和联系方式。
4. 在“Agent 身份设定”中写清企业定位、优势、语言偏好和禁止事项。
5. 如需使用客户背调的公开搜索，在“客户背调”页右上角配置 Tavily API Key。

公司资料和 Agent 身份会作为所有业务模块的默认背景。资料越完整，AI 的输出越接近真实业务。

### 2.4 第一次完整体验

建议按下面顺序完成第一次使用：

1. 在“公司设置”补齐产品和目标市场。
2. 在“文档库”上传公司简介、产品目录和价格表。
3. 在“客户管理”添加一个现有客户。
4. 进入“客户开发”或“网站诊断”，选择一个客户或参考文档后对话。
5. 在“对话记录”查看并继续刚才的会话。
6. 在“定时任务”创建一个工作日客户跟进任务。

## 3. 系统结构与数据关系

### 3.1 账号、空间和公司

系统采用“账号 → 独立空间 → 多家公司”的结构。

| 层级 | 含义 | 主要数据 |
|---|---|---|
| 账号 | 登录身份 | 邮箱、密码、独立工作空间 |
| 工作空间 | 个人数据边界 | 模型配置、搜索配置、定时任务、对话 |
| 公司 | 业务数据边界 | 公司资料、客户、订单、文档库、背调报告 |

一个账号可以添加多家公司，并通过左上角下拉框切换。客户、订单、文档库、背调报告和业务对话按公司隔离。

### 3.2 核心数据关系

| 数据对象 | 归属 | 关联对象 | 用途 |
|---|---|---|---|
| 公司资料 | 公司 | 所有 AI 模块 | 提供产品、市场和身份背景 |
| 客户 | 公司 | 订单、文档库、背调报告、对话 | 客户档案与跟进中心 |
| 订单 | 公司、客户 | 商品明细、报价 | 记录金额、交期和履约状态 |
| 文档库 | 公司 | 文件、客户、对话 | 保存产品目录、报价、合同和资料 |
| 对话 | 公司、可选客户 | 业务技能、所选文档 | 保存分析与生成过程 |
| 背调报告 | 公司、可选客户 | 搜索来源、深度检测层 | 验证客户真实性和风险 |
| 定时任务 | 工作空间、公司 | 业务技能、运行结果 | 周期性生成分析或内容 |

客户与文档库是多对多关系。一个客户可以关联多个文档库，一个文档库也可以服务多个客户。对话可以选择一个客户和一个已提取文字的文档作为本轮上下文。

### 3.3 工作流总览

```text
公司定位与 Agent 身份
          |
          v
客户资料 + 订单 + 文档库 + 对话历史
          |
          v
客户开发 / 网站诊断 / 社媒营销 / LinkedIn / 海关数据 / 客户背调
          |
          v
线索、诊断、内容、风险报告、采购商清单
          |
          v
客户管理 / 订单 / 文档生成 / 定时任务 / 对话记录
```

所有业务模块不是互相孤立的工具。前面模块产生线索或判断，后续模块负责验证、入库、触达、报价和持续跟进。

## 4. 工作台通用操作

### 4.1 左侧导航

左侧栏分为五组：

| 分组 | 模块 |
|---|---|
| 工作台 | 今日简报 |
| 获客引流 | 客户开发、网站诊断、社媒营销、LinkedIn、海关数据 |
| 销售转化 | 客户管理、文档库、文档生成 |
| 工具 | 客户背调、定时任务 |
| 历史 | 对话记录 |

### 4.2 对话顶部控制项

对话区顶部提供以下控制：

| 控件 | 作用 | 使用建议 |
|---|---|---|
| 关联客户 | 将当前客户资料加入本轮对话 | 做客户分析、邮件、报价时选择 |
| 参考文档 | 将所选文档的已提取文字加入上下文 | 产品目录、合同、海关数据等场景使用 |
| 联网搜索 | 使用已配置的 Tavily 预搜索公开资料 | 需要实时或公开网页来源时开启 |
| Hermes 工具 | 允许调用本机浏览器、搜索和文件工具 | 网站诊断、深度检索、生成文件时保持开启 |
| 新对话 | 清空当前上下文并开始新会话 | 切换任务或旧会话连续报错时使用 |
| 停止 | 中止当前生成任务 | 发现方向错误或等待过久时使用 |

纯文本撰写可以关闭 Hermes 工具，以获得更快回复。涉及实时网页、网站检查、文件读取或多步骤研究时，需要开启 Hermes 工具。

### 4.3 工具任务的期望

网站诊断、客户背调和多轮检索可能持续数分钟。系统会让 Hermes 在运行预算结束时主动收尾，应用保留额外时间保存结果。

看到“正在调用工具”时不要立即点击“继续”。工具任务尚未结束时发送“继续”，可能产生新的会话分支或错误上下文。若任务明确失败，优先新建对话重新执行。

## 5. 配置与基础资料模块

### 5.1 公司设置

入口：左上角公司名称旁的“⚙”。

主要字段：

| 字段 | 建议填写内容 |
|---|---|
| 公司名称 | 对外正式名称 |
| 联系人 | 主要业务联系人 |
| 邮箱 | 公司业务邮箱 |
| 官网 | 公司或独立站地址 |
| 行业 | 用一到两句话写清行业位置 |
| 地址 | 工厂或办公地址 |
| 主营产品 | 产品名称、规格、能力、核心优势 |
| Agent 身份设定 | 角色、语言、风格、业务纪律和禁止事项 |

建议的 Agent 身份示例：

```text
你是我们的外贸销售顾问。公司主营太阳能支架，目标市场是德国和西班牙，
主要客户是安装商和区域分销商。回答时优先给出可执行动作，所有价格、
认证和交期必须来自我提供的资料，不得猜测。默认使用简体中文，
给客户的英文内容与中文说明分开输出。
```

添加公司和切换公司会使当前业务数据范围发生变化。切换前确认客户和文档属于目标公司。

### 5.2 模型设置

入口：左下角“⚙️”。

填写模型名称和 API Key。API Key 在本机加密保存，接口不会返回明文。模型不可用时，先检查：

1. API Key 是否有效。
2. 模型名称是否可用。
3. 服务商账户是否有额度。
4. 本机网络是否能访问模型服务。

### 5.3 Tavily 搜索设置

入口：“客户背调”页右上角“搜索配置”。

Tavily 主要用于公开信息搜索。未配置时，客户背调的普通“搜索公开信息”不能获得搜索结果；Hermes 自带搜索工具仍可在工具模式下独立工作。

## 6. 业务模块使用说明

### 6.1 今日简报

用途：整理当天最值得处理的客户、订单、跟进事项和业务行动。

使用步骤：

1. 选择“今日简报”。
2. 可选择一个客户，也可以不选客户查看全局情况。
3. 输入简报范围和时间要求。
4. 需要公开新闻或实时信息时开启“联网搜索”。

示例：

```text
生成今天的早安简报。重点列出：
1. 报价中超过 3 天未跟进的客户；
2. 本周需要交付的订单；
3. 3 个今天应优先联系的对象和原因。
```

主要输出：优先级列表、待办事项、客户跟进建议、订单提醒。

与其他模块的关系：读取客户和订单数据，参考对话记录，并可调用定时任务结果。后续行动通常在“客户管理”和“客户开发”中完成。

边界：简报不是自动 CRM 提醒，也不会替你发邮件。

### 6.2 客户开发

用途：寻找潜在客户、设计搜索路径、生成开发信和建立跟进节奏。

使用步骤：

1. 明确“卖什么、卖到哪里、卖给谁”。
2. 选择目标客户，可为空。
3. 开启 Hermes 工具进行多通道搜索。
4. 要求输出公司名、官网、国家、买家类型、联系方式和开发理由。
5. 确认线索后，要求 AI 将指定公司写入客户库。

示例：

```text
我们出口工业水泵，目标市场是美国德州，买家类型是区域分销商和维修服务商。
请找 20 家真实公司，按 A/B/C 分级，提供官网、所在城市、主要产品线和
公开联系方式。每条结论附来源链接，没有来源的信息标“待验证”。
```

将线索写入客户库时，可直接说：

```text
把上面确认的 10 家公司写入我的客户库，自动去重。
```

主要输出：目标客户画像、搜索关键词、潜在线索、分级表、开发信和跟进计划。

与其他模块的关系：线索进入“客户管理”；重要客户进入“客户背调”；产品资料来自“文档库”；开发信可继续交给“文档生成”形成报价或提案。

边界：搜索到的联系人、邮箱和采购意图需要人工核对。系统不会自动加 LinkedIn 好友、自动发送邮件或保证线索质量。

### 6.3 网站诊断

用途：从公开页面、搜索数据和第三方公开评价中，分析网站获客与询盘转化问题。

使用步骤：

1. 选择“网站诊断”。
2. 粘贴完整网址，并说明是自有网站还是竞品网站。
3. 写明目标市场、目标客户和希望重点检查的页面。
4. 保持“Hermes 工具”开启。
5. 等待页面访问、搜索和整理完成。

示例：

```text
检查 https://example.com/。
这是我们的独立站，目标客户是德国工业采购商。
重点检查首页价值主张、产品页、询盘路径、移动端体验、信任元素，
并对比 3 个德国同行。所有结论附来源链接。
```

主要输出：页面问题、转化路径问题、信任元素缺失、竞品对比、优先级和改进行动。

数据来源：

| 数据类型 | 来源 |
|---|---|
| 页面内容 | 浏览器实际打开的首页、产品页、About、Contact |
| 技术公开文件 | robots.txt、sitemap.xml、公开链接 |
| 流量参考 | 第三方公开流量估算页面 |
| 口碑 | Trustpilot、BBB 等公开评价或投诉 |
| 竞争格局 | 搜索引擎和竞品公开页面 |

与其他模块的关系：诊断结果可以转化为“客户开发”的差异化卖点，也可以交给“社媒营销”和“LinkedIn”形成内容选题。

边界：没有授权后台数据时，无法读取真实 UV、询盘数、订单、广告花费和转化率。第三方流量是估算，不等同于网站后台数据。

### 6.4 社媒营销

用途：为 Facebook、Instagram、TikTok、YouTube 规划内容并生成可发布文案。

使用步骤：

1. 写明平台、目标国家、客户类型和发布频率。
2. 提供工厂、产品、认证、案例或展会的真实素材。
3. 指定内容目标，如曝光、建立信任、引导询盘或推广新品。
4. 要求输出内容日历、素材清单、文案、Hashtags 和 CTA。

示例：

```text
我们是一家太阳能支架工厂，目标客户是德国安装商。
请规划未来 4 周 Facebook、Instagram 和 TikTok 内容，每周每平台 2 条。
重点展示防腐工艺、安装流程、质量检验和项目案例。
为每条内容写标题、正文、Hashtags、CTA 和所需素材。
```

主要输出：平台策略、内容主题、周历、帖子文案、短视频脚本、素材清单。

与其他模块的关系：网站诊断提供转化问题，LinkedIn 负责更专业的客户开发内容，文档库提供产品事实和案例素材。

边界：系统生成内容和计划，不自动登录平台发帖，也不保证播放量或询盘。

### 6.5 LinkedIn 营销

用途：优化 LinkedIn 主页，规划专业内容，并建立目标公司、决策人和触达话术流程。

使用步骤：

1. 说明目标是个人主页、公司主页还是客户开发。
2. 说明自己的会员等级：免费 Basic、Premium Business 或 Sales Navigator。
3. 提供目标国家、行业、公司规模、客户类型和职位。
4. 先做客户画像和搜索词，再写连接留言或 InMail。

示例：

```text
我们卖汽车轮毂，目标市场是美国，客户是轮胎改装店和区域经销商。
我使用 LinkedIn 免费版。请先给出客户画像、英文搜索关键词和决策人职位，
再为 5 家目标公司各写一版 200 字符以内的连接邀请留言。
```

主要输出：主页优化任务、内容计划、搜索词、客户优先级、联系人路径和触达文案。

与其他模块的关系：目标客户来自“客户开发”或“海关数据”；公司真实性由“客户背调”验证；产品参数来自“文档库”；确认后的客户写入“客户管理”。

边界：不会自动加好友、自动私信或绕过 LinkedIn 风控。会员功能以用户账户实际显示为准。

### 6.6 海关数据

用途：从进出口记录中筛选真实采购商、分析采购模式和安排开发优先级。

#### 有数据文件

1. 在“文档库”上传 CSV 或 Excel。
2. 进入“海关数据”，在“参考文档”中选择该文件。
3. 写明产品、HS 编码、目标国家、MOQ 和数据统计期。
4. 要求按产品、地理、采购量频和公司类型四层筛选。

示例：

```text
这是我导出的美国进口记录。我们出口家具五金，HS 编码 8302，
目标市场美国，MOQ 为 500 件。请筛选持续进口、产品匹配的采购商，
分析采购频率、数量、季节性和供应商集中度，按 P1-P4 排序，
并标注文件名、列名和行号。
```

#### 没有官方数据文件

可以输入公司名、官网和产品，要求查找公开提单索引和网页记录。此类结果只能作为初步线索，不能写成官方海关数据。

主要输出：采购商清单、采购频率、数量趋势、供应商集中度、优先级、市场洞察和触达建议。

与其他模块的关系：采购商清单进入“客户管理”，重点客户进入“客户背调”，随后生成开发信、报价和跟进任务。

当前文件限制：

| 项目 | 限制 |
|---|---|
| 上传文件大小 | 最大 12 MB |
| CSV/文本提取 | 最大 100000 字符 |
| Excel 提取 | 最多 10 个工作表，每表最多 500 行、30 列 |
| 对话直接附加文档 | 单个文档正文最多 12000 字符 |

数据量较大时，应按季度、国家或产品拆分文件，或先汇总关键列。不要把超过上下文限制的文件当成已完整分析。

边界：系统不附带全球海关数据库。没有文件时，公开渠道覆盖有限，搜不到不能证明没有进口。

### 6.7 客户管理

用途：维护客户主数据、联系方式、等级、买家类型、备注、文档库和订单。

新增客户：

1. 进入“客户管理”。
2. 点击“＋ 添加客户”。
3. 填写公司名称、联系人、邮箱、国家、等级和买家类型。
4. 点击保存。

客户详情：

1. 点击客户行打开详情。
2. 查看联系人、职位、邮箱、国家、买家类型、主营品类和网站。
3. 关联或取消关联文档库。
4. 新增和编辑订单。
5. 点击“与此客户对话”进入带客户上下文的会话。

客户等级建议：

| 等级 | 含义 | 行动 |
|---|---|---|
| A | 匹配度高、采购潜力明确 | 优先背调、报价和跟进 |
| B | 有潜力但信息或需求待确认 | 继续验证和培育 |
| C | 暂不优先或匹配度较低 | 低频维护 |

CSV 导入：

1. 点击“CSV 导入”。
2. 使用 UTF-8 编码 CSV。
3. 表头必须包含 `name`，可先导出客户列表参考字段。
4. 单次最多 1000 行，文件最大 2 MB。
5. 任意一行错误会整体拒绝，避免留下半份数据。

订单子模块：

在客户详情点击“新增订单”，可填写订单号、币种、状态、交期、付款条款和多条商品明细。单价可留空表示待谈。订单状态按“报价中 → 已下单 → 已出货 → 已完成”流转，报价中和已取消订单可以删除。

与其他模块的关系：客户是 AI 对话、客户背调、订单、文档库关联和今日简报的共同中心。没有写进客户管理的线索不会自动形成客户档案。

### 6.8 文档库

用途：保存并提取公司业务资料，为 AI 分析提供可信事实来源。

创建文档库：

1. 点击“文档库”。
2. 点击“＋ 添加文档库”。
3. 输入库名称。
4. 可关联电脑上的本地文件夹，也可以留空后直接上传文件。

上传与扫描：

1. 选择当前文档库。
2. 上传支持的文件，或点击“扫描文件夹”。
3. 点击文档的“查看文字”检查提取结果。
4. 点击“下载”获取原文件。

支持格式：

```text
TXT / MD / CSV / PDF / DOCX / XLSX / PNG / JPG / JPEG / WEBP
```

提取规则：

| 格式 | 当前行为 |
|---|---|
| TXT、MD、CSV | 读取 UTF-8 文本 |
| DOCX | 读取段落和表格 |
| XLSX | 读取前 10 个表的各前 500 行、30 列 |
| PDF | 提取前 50 页文本 |
| 图片和研究图纸 | 保存原文件，不执行 OCR |
| 扫描 PDF | 没有文字层时不会假装完成 OCR |

与其他模块的关系：文档库为网站诊断、客户背调、社媒营销、海关数据和文档生成提供事实材料。客户详情可以关联文档库，让客户和资料形成稳定关系。

建议的库结构：

```text
公司资料/
产品目录/
价格与报价/
认证与检测/
客户合同/
物流与单证/
海关数据/
```

### 6.9 文档生成

用途：根据客户、订单和产品资料，起草报价单、形式发票、商业发票、装箱单、合同、方案和提案。

使用步骤：

1. 选择“文档生成”。
2. 选择关联客户。
3. 选择参考文档，例如产品目录或价格表。
4. 保持 Hermes 工具开启，便于读取文件或生成 Office 文件。
5. 写明文档类型、语言、币种、贸易术语、交期和输出格式。

示例：

```text
为当前客户生成英文形式发票草稿，币种 USD，贸易术语 FOB Shanghai，
付款条件 30% 定金、70% 发货前付清。产品、规格和单价只能来自所选产品目录，
缺少的银行信息或地址标为待确认，不得猜测。
```

主要输出：结构化正文、表格、报价明细、条款和文件草稿。

与其他模块的关系：客户模块提供买方资料，订单模块提供数量和价格，文档库提供产品事实和历史单证，对话记录保留生成过程。

边界：正式单证发出前必须人工核对抬头、价格、税号、银行信息和贸易条款。文件能否直接生成到 Word/Excel 取决于本机 Hermes 工具和所用模型能力。

### 6.10 客户背调

用途：在合作前确认客户公司真实性、业务匹配度、公开风险和联系人线索。

普通公开搜索：

1. 打开“客户背调”。
2. 配置 Tavily API Key。
3. 输入公司名、域名、邮箱或核验问题。
4. 可关联现有客户。
5. 点击“搜索公开信息”。

深度背调：

1. 输入邮箱或域名。
2. 可关联现有客户。
3. 点击“深度背调”。
4. 查看公司身份、风险标记、检测层、建议和来源。

常见检测维度：

| 维度 | 目的 |
|---|---|
| 官网和 About/Contact | 核对公司、地址和联系方式 |
| WHOIS | 查看域名注册时间和基础信息 |
| DNS/MX | 判断企业邮箱能力 |
| 邮箱平台 | 识别邮箱服务类型 |
| 技术栈 | 了解网站技术线索 |
| 制裁名单 | 检查公开风险名单 |
| LinkedIn | 核对公司页和公开员工线索 |

示例：

```text
请背调 ABC Trading GmbH，官网 abc.example，联系邮箱 buyer@abc.example。
重点核对公司身份、联系信息一致性、域名年龄、制裁风险和企业邮箱，
按风险等级输出，并为每条重要结论附来源。
```

与其他模块的关系：背调报告可以关联客户，帮助调整客户等级、报价条件和跟进策略。背调结果也可以作为文档生成和开发信的风险依据。

边界：公开信息不能代替正式信用调查、律师意见或银行尽调。查不到不等于不存在。

### 6.11 定时任务

用途：按天、工作日或每周自动生成业务简报和内容草稿。

使用步骤：

1. 打开“定时任务”。
2. 点击预设模板，或点击“＋ 新建任务”。
3. 填写任务名称和执行指令。
4. 选择业务技能。
5. 设置频率、时间和每周执行日。
6. 保存后可点击“立即执行”测试。
7. 在“最近运行”查看成功、失败和结果。

示例：

```text
每个工作日 09:00 汇总：
1. 今天需要跟进的 A/B 级客户；
2. 报价中超过 3 天未推进的订单；
3. 每个客户建议的下一步动作。
输出简洁表格，不要自动发送邮件。
```

与其他模块的关系：任务可以调用任意业务技能，并读取当前公司的客户、订单和资料。运行结果用于今日简报和跟进决策。

边界：只有应用进程运行时才会执行到期任务。任务只生成文本，不执行 shell、不自动发送邮件、不自动发帖，也不替代人工确认。

### 6.12 对话记录

用途：查看、恢复或删除历史会话，保持业务分析可追溯。

使用步骤：

1. 打开“对话记录”。
2. 点击“打开”恢复会话。
3. 点击“删除”移除会话。
4. 正在生成的会话不能删除。

与其他模块的关系：客户开发、网站诊断、社媒、LinkedIn、海关数据和文档生成的过程都会进入对话记录。恢复会话时会根据最后一个技能回到对应业务入口。

使用建议：

- 一个任务一个会话，避免多个目标混在一起。
- 工具任务失败后新建会话，不要在错误上下文里反复“继续”。
- 重要结论应同步到客户管理、文档库或订单，不要只留在聊天记录中。

## 9. 数据保存、备份与安全

当前应用数据主要保存在：

```text
login-demo/data/accounts.sqlite3
login-demo/data/model-encryption.key
login-demo/data/workspaces/
login-demo/data/hermes-workspaces/
```

`model-encryption.key` 用于解密模型和搜索 API Key。备份时必须与数据库一起保存。丢失密钥后，已有 API Key 不能恢复，需要重新填写。

建议备份整个 `login-demo/data` 目录。备份前可以停止应用，避免数据库正在写入。

安全边界：

- API Key 不出现在普通查询接口中。
- 密码以带随机盐的 PBKDF2 哈希保存。
- 业务查询按账号空间和公司隔离。
- 上传文件使用服务端生成的文件名。
- 应用默认只监听 `127.0.0.1`。
- 外部搜索内容、模型输出和公开网页都可能不准确，需要人工复核。

## 10. 故障排查

### 10.1 无法登录

先确认使用的是“登录”还是“注册”。新账号必须先注册；密码长度必须为 8 到 128 位。

服务重启后如果登录状态失效，是随机会话密钥发生了变化。重新登录即可，账号数据仍在。

### 10.2 模型没有回复

检查模型设置中的模型名称、API Key、账户额度和网络。模型服务不可用时，所有 AI 模块都会受影响。

### 10.3 一直在思考

网站诊断和背调会执行多轮网页访问。开启 Hermes 工具时，长任务通常需要数分钟。

当前版本的 Hermes 运行预算为 240 秒，应用进程留出额外时间收尾。不要同时反复发送“继续”。如果任务已报错，新建会话重新描述目标。

### 10.4 为什么很多数据写“待验证”

系统只应把实际打开页面、实际搜索或用户提供的数据写成事实。没有网站后台、GA、广告账户或海关数据时，UV、询盘、订单、采购量等只能标为待验证。

确保：

1. “Hermes 工具”已开启。
2. Tavily 已配置，或 Hermes 自带搜索可用。
3. 没有只给一个模糊公司简称。
4. 没有让系统猜测 HS 编码、价格、认证和交期。

### 10.5 文档没有提取到文字

可能原因：

- PDF 是扫描件，没有文字层。
- 图片和图纸当前不做 OCR。
- Office 文件损坏或超出解析限制。
- 文本不是 UTF-8。
- Excel 行数、列数或工作表数超过提取上限。

原文件仍会保存，可以先下载检查，或把关键内容拆成更小的文件。

### 10.6 海关数据分析不完整

检查文件是否超过 12 MB、是否超过 10 个表、单表是否超过 500 行或 30 列。对话附加文档最多使用 12000 字符。建议按季度、国家或产品拆分。

### 10.7 定时任务没有执行

定时任务依赖应用进程持续运行。电脑休眠、应用关闭或服务停止时不会执行。查看“最近运行”中的失败原因，并先用“立即执行”验证指令和模型配置。

### 10.8 客户或文档看不到

确认当前左上角公司是否正确。客户、订单、文档库、背调报告和商业对话按公司隔离。切换公司后不会显示其他公司的业务数据。

## 11. 推荐的标准业务流程

### 11.1 新公司一周初始化

| 时间 | 动作 | 产出 |
|---|---|---|
| 第 1 天 | 完善公司设置和 Agent 身份 | AI 业务背景 |
| 第 2 天 | 建立产品目录、报价和认证文档库 | 可信资料库 |
| 第 3 天 | 导入或新增现有客户 | 客户主数据 |
| 第 4 天 | 做一轮网站诊断和竞品分析 | 获客改进清单 |
| 第 5 天 | 制定社媒和 LinkedIn 内容计划 | 内容日历 |
| 第 6 天 | 用海关数据或客户开发筛选新线索 | 目标客户清单 |
| 第 7 天 | 背调重点客户并建立定时跟进任务 | 可执行销售计划 |

### 11.2 从海关数据找到客户并推进

1. 上传海关数据并按季度拆分。
2. 在“海关数据”里筛选持续采购、产品匹配的进口商。
3. 选择 A 级客户做“客户背调”。
4. 在“客户管理”中补齐联系人、等级和备注。
5. 关联产品目录和报价文档库。
6. 在“客户开发”里生成定制开发信。
7. 获得回复后，用“文档生成”制作报价单或 PI。
8. 在客户详情建立订单并更新状态。
9. 用“定时任务”每周生成跟进清单。

### 11.3 从网站诊断到内容营销

1. 在“网站诊断”检查首页、产品页和询盘路径。
2. 保存三项最重要的问题和三项可差异化卖点。
3. 在“社媒营销”把卖点转为 4 周内容计划。
4. 在“LinkedIn”建立专业形象和客户开发内容。
5. 在“客户开发”用诊断结论作为开发信切入口。
6. 将有效表达沉淀到公司 Agent 身份或文档库。

## 12. 使用原则

1. 先补齐公司资料，再做行业分析。
2. 一个会话只解决一个清晰任务。
3. 把客户、订单和可靠资料沉淀到对应模块，不要只留在聊天里。
4. 公开网页、第三方数据和模型输出都要看来源。
5. 价格、认证、交期、制裁和合规结论必须人工复核。
6. 对外发送前核对收件人、抬头、金额、币种和贸易条款。
7. 大规模数据先拆分，不要让不完整上下文产生完整分析假象。

## 13. 能力边界

系统不包含：

- 全球官方海关数据库。
- 客户银行流水、私人邮箱或未公开采购数据。
- 网站后台、Google Analytics、Shopify 或广告账户的自动访问。
- 自动发送邮件、自动发帖、自动加好友。
- 法律、信用、税务或制裁合规的最终结论。

系统适合做研究、整理、初步筛选、内容草稿和流程辅助。正式商业决策仍由业务人员负责。
