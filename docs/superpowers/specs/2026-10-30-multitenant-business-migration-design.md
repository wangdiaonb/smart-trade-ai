# 多租户业务迁移设计

## 目标

将独立登录演示版扩展为 Smart Trade 业务应用的独立多租户版本。登录用户获得彼此隔离的公司工作空间，并可以使用迁移后的业务模块。现有试用期、许可证和激活控制继续保留；本设计不删除或绕过这些限制。

## 范围

迁移覆盖原应用中的主要业务领域，并按阶段推进：

1. 身份认证与工作空间上下文。
2. 公司和客户管理。
3. AI 对话、对话历史、记忆和技能路由。
4. 订单、报价、文档库、模板和技术图纸。
5. 定时任务、OSINT、邮件、LinkedIn 及相关外部能力。
6. 完整的登录后工作台界面。

第一版采用“每个账号一个默认工作空间”。工作空间成员、邀请、团队、计费和第三方身份认证，等核心迁移稳定后再扩展。

## 租户模型

- `users` 保存登录身份和密码哈希。
- `workspaces` 保存公司工作空间，由用户拥有。
- 迁移后的业务表都增加非空的 `workspace_id` 外键。
- 登录会话只保存 `user_id`；服务端根据用户解析其工作空间，绝不信任客户端提交的用户 ID 或工作空间 ID。
- 所有读取、更新、删除和业务操作都必须限制在当前工作空间内。缺少权限或工作空间不匹配时，返回安全的“不存在”或“禁止访问”响应，不泄露其他工作空间的数据。
- 原有本地数据不会自动暴露给新账号。导入或迁移时，必须明确指定其归属工作空间。
- 工作空间文件保存在受控的工作空间目录下；路径由服务端生成，浏览器不能提交任意文件系统路径。

## 应用架构

`login-demo/` 应用将成为新的登录后业务外壳。其 FastAPI 应用负责登录、会话管理、工作空间解析、静态资源和迁移后的 API 路由。业务逻辑按职责拆分迁移，而不是整体导入原 `trade` 包，从而建立明确的租户边界。迁移初期可以使用原逻辑的适配器，但适配器必须接收已解析的工作空间上下文，不能提供无作用域的数据库访问。

浏览器始终使用同源 API。未登录请求只能访问登录/注册页面和认证接口。登录后请求由服务端提供工作空间上下文。外部服务和定时任务必须显式接收工作空间 ID，并读取该工作空间自己的凭据和配置。

## 迁移阶段

### 第一阶段：身份认证与工作空间上下文

注册时创建工作空间，增加会话到工作空间的解析、请求依赖、数据库迁移工具和隔离测试。在这道边界得到验证前，不启用业务功能。

### 第二阶段：公司和客户数据

迁移公司、客户、联系人和基础设置的增删改查。所有仓储函数都增加工作空间过滤，并验证两个账号不能读取或修改对方的数据。

### 第三阶段：核心工作台

迁移聊天流式响应、对话历史、记忆、提示词/技能路由和 Agent 上下文。对话和记忆记录必须携带工作空间作用域；流式错误不能泄露其他工作空间的数据。

### 第四阶段：业务操作

迁移订单、报价、文档库、模板、文档任务和技术图纸。文件存储和数据库记录必须使用同一套工作空间归属校验。

### 第五阶段：自动化与外部能力

迁移定时任务绑定、OSINT、邮件情报、LinkedIn 相关流程和外部 API 配置。后台任务必须显式携带工作空间上下文，不能使用进程级全局当前用户。

### 第六阶段：界面复刻

将原工作台导航和面板迁移到登录后的应用外壳中。把原先依赖客户端选择公司的逻辑替换为服务端解析的工作空间。登录/注册页面与业务工作台保持分离。

## 错误处理与安全

- 无效登录继续返回通用的 401 响应。
- 无效输入返回校验错误，不返回堆栈信息。
- 跨工作空间访问资源时，返回“不存在”或“禁止访问”，不泄露其他工作空间的记录是否存在。
- 密码继续使用带盐 PBKDF2 哈希；会话继续使用签名、HttpOnly、SameSite=Lax Cookie。
- 任何 API 都不能把浏览器提交的 `user_id` 或 `workspace_id` 作为授权依据。
- 文件上传和下载必须在访问文件系统前验证归属关系。
- 试用期、许可证和激活判断继续使用现有授权逻辑。

## 验证策略

每个阶段都必须先增加单元测试和 API 测试，再开始实现。必须覆盖以下回归场景：

- 注册会准确创建一个默认工作空间。
- 两个账号可以同时使用同一业务功能，但看不到对方的记录或文件。
- 伪造或不匹配的工作空间标识不能改变授权结果。
- 登录和未登录状态的界面都能正确渲染。
- 原有许可证/试用期测试在迁移后的服务中保持不变并通过。
- 独立应用没有无作用域导入，也没有绕过租户上下文的直接访问路径。

## 验收标准

- 用户可以注册、登录并进入默认公司工作空间。
- 所有迁移后的业务数据都归属于某个工作空间，并按当前登录工作空间过滤。
- 原有业务领域按上述六个阶段完成迁移，每个边界都有测试。
- 新应用可以独立运行，不依赖登录系统绕过原有许可证限制。
